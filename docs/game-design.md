# 헤드밴드 게임 기획서 (가제: 거짓말 헤드밴드)

- 작성일: 2026-11-16
- 상태: 초안 v0.3

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 1:1 추리 대화 게임 (헤드밴드 게임 + 스무고개 + 거짓말 간파) |
| 한 줄 소개 | 서로 상대의 제시어만 보면서 예/아니오 질문을 주고받는다. 단, 양쪽 모두 거짓말을 할 수 있다. 플레이어는 AI의 버릇으로 거짓말을 잡아내고, AI는 플레이어의 답을 항상 의심한다. |
| 플레이 시간 | 1판 5~10분 |
| 플랫폼 | Python + Gradio 웹 (이후 pywebview로 데스크톱 앱 전환 검토) |
| AI | 로컬 LLM (Ollama, `qwen3:14b`) |
| 아트 | ComfyUI로 생성한 오리지널 캐릭터 스프라이트 |

### 재미의 핵심
1. **추리**: 제한된 질문으로 내 제시어를 좁혀가는 재미
2. **간파**: AI 캐릭터의 버릇을 학습해서 거짓말을 잡아내는 쾌감
3. **심리전**: 의심하는 AI를 속여 넘기는 재미
4. **긴장감**: 질문 횟수가 한정돼 있어서, 속으면 손해를 보고 간파하면 만회한다

## 2. 기본 룰

### 2.1 준비
- 플레이어와 AI에게 각각 제시어가 1개씩 배정된다.
- 플레이어는 **AI의 제시어**를 볼 수 있고, 자신의 제시어는 볼 수 없다.
- AI도 마찬가지다. 코드가 AI에게 플레이어 제시어만 전달한다.
- 제시어 카테고리는 공개한다 (예: 동물, 음식, 직업, 사물).

### 2.2 턴 진행
한 라운드는 다음 순서로 진행한다.

1. **플레이어 질문**
   - 플레이어가 자기 제시어에 대해 **예/아니오로 답할 수 있는 질문**을 한다.
   - AI가 답한다 (2.3 참고). **이때 AI가 거짓말을 할 수 있다** (3장).
   - 답변 직후 플레이어는 간파를 선언할 수 있다 (6장).
2. **AI 질문**
   - AI가 자기 제시어에 대해 예/아니오 질문을 하면 플레이어가 버튼으로 답한다. **이때 플레이어가 거짓말을 할 수 있다** (5장).
   - AI는 플레이어의 답을 항상 의심하고, 의심이 크면 간파를 선언한다 (5.3).
3. 각자 자기 턴에 질문 대신 **정답 도전**을 할 수 있다.

### 2.3 답변 규칙 (양쪽 공통)
- 답은 **`예` / `아니오` / `애매함`** 셋 중 하나다.
  - `애매함`: 기준에 따라 답이 갈려서 예/아니오로 딱 잘라 말하기 어려운 질문 (예: 바나나에게 "비싸?", "커?")
  - 목적: 판단이 갈리는 질문 때문에 진실한 답이 거짓말처럼 보이거나, 억울한 심판 경고를 받는 상황을 막는다.
- 예/아니오로 답할 수 없는 질문(예: "무슨 색이야?")은 무효 처리한다. "예/아니오로 답할 수 있게 물어봐 줘"라고 안내하고 **토큰은 쓰지 않는다**.
- AI는 답과 함께 **정보가 없는 짧은 반응 대사**를 붙일 수 있다 (예: "음... 예. 그렇다고 해두지."). 대사에는 제시어에 대한 추가 힌트를 넣지 않는다.

| 질문 (제시어: 바나나) | 답 |
|---|---|
| 먹을 수 있어? | 예 |
| 살아있는 동물이야? | 아니오 |
| 비싸? | 애매함 |
| 무슨 색이야? | 무효 (토큰 소모 없음) |

### 2.3.1 애매함 남용 방지
- **토큰 환급**: `애매함` 답을 받은 쪽은 질문 토큰을 돌려받는다. 애매한 질문으로 정보를 못 얻었는데 토큰까지 잃으면 억울하기 때문이다.
- **플레이어의 회피 방지**: 플레이어가 명확한 질문에 `애매함`을 누르면 심판 LLM이 경고한다 (5.2 참고).
  - 예: AI 제시어가 "펭귄"인데 "동물이야?"에 `애매함`을 누름 → "이 질문은 예/아니오로 답할 수 있어요." 경고
- **AI**: 답 판정 LLM이 `애매함`이라고 판단한 경우에만 `애매함`으로 답한다. AI가 회피 목적으로 쓰지 않는다.
- 연속으로 애매한 질문을 반복하는 경우를 막기 위해, 같은 쪽이 `애매함` 답을 받는 횟수에 제한을 둘지는 플레이테스트 후 결정한다.

### 2.4 질문 횟수 제한 (핵심 룰)
- 각자 **질문 토큰 15개**로 시작한다 (밸런스 조정 대상).
  - 예/아니오 답은 정보량이 적어서 서술형일 때(10개)보다 늘렸다. 플레이 시간 5~10분을 넘지 않도록 15개로 잡았다.
- 질문 1회에 토큰 1개를 쓴다. 단, 무효 질문과 `애매함` 답을 받은 질문은 토큰을 쓰지 않는다.
- 토큰이 0이 되면 더 이상 질문할 수 없고 정답 도전만 할 수 있다.

> 이 룰이 있어야 거짓말과 간파가 의미를 가진다. 질문을 무제한으로 할 수 있다면 같은 질문을 다시 해서 확인하면 그만이라 거짓말이 아무 위협이 되지 않는다.

### 2.5 정답 도전
- 정답 도전 기회는 **3회**다.
- 틀리면 질문 토큰 1개를 잃는다.
- 비슷한 표현은 정답으로 인정한다 (예: "강아지" = "개"). 판정은 LLM이 하고 최종 확인은 코드가 한다.

### 2.6 승패
- 먼저 자기 제시어를 맞힌 쪽이 승리한다.
- 둘 다 토큰과 정답 기회를 모두 소진하면 무승부다.
- 점수: 남은 토큰 + 간파 성공 보너스 + AI를 속인 횟수 보너스 (랭킹/기록용)

## 3. AI 거짓말 시스템

### 3.1 원칙: 거짓말 여부는 코드가 정한다
LLM에게 알아서 거짓말하게 맡기면 거짓말 기록을 정확히 추적할 수 없고 텔 연출과도 맞출 수 없다. 답이 예/아니오라서 거짓말은 **답을 뒤집는 것**으로 충분하다.

```
플레이어 질문
   │
   ▼
① LLM: 진실한 답 판정 → {"answer": "예" | "아니오" | "애매함" | "무효"}
   │   무효 → 안내 후 종료 (토큰 소모 없음)
   ▼
② 게임 엔진: 이번에 거짓말할지 결정 (남은 거짓말 횟수, 캐릭터 성향, 확률)
   │
   ├─ 진실 → 그대로
   └─ 거짓 → 예 ↔ 아니오 뒤집기
   │
   ▼
③ LLM: 캐릭터 말투의 짧은 반응 대사 생성 (정보 없음)
   │
   ▼
④ 연출: 거짓말이면 텔 이미지 출력 / 진실이면 가끔 페이크 텔
   │
   ▼
⑤ 기록: 턴 번호, 질문, 진실한 답, 실제 답, 거짓 여부 저장
```

### 3.2 거짓말 규칙
- AI는 게임당 **최대 N회** 거짓말할 수 있다 (난이도별 1~3회).
- `애매함` 답에는 거짓말하지 않는다.
- 첫 2개 질문에서는 거짓말하지 않는다 (초반에 플레이어가 버릇을 관찰할 시간을 준다).
- 연속으로 거짓말하지 않는다.
- 남은 거짓말 횟수는 UI에 표시한다 (예: 🤥 × 2). 플레이어가 "아직 거짓말이 남았다"는 긴장감을 느끼게 한다.

## 4. 텔(버릇) 시스템

### 4.1 개념
AI 캐릭터가 거짓말을 할 때 짧은 순간 특정 동작을 보인다. 플레이어는 이 버릇을 학습해서 거짓말을 간파한다.

- 캐릭터마다 **고유 버릇 1개**가 있다 (7.2 캐릭터 목록).
- 처음에는 버릇을 알려주지 않는다. 몇 번 속고 나서 스스로 깨닫게 하는 것이 재미의 핵심이다.

### 4.2 평소 움직임 속의 동요 (페이크 텔 없음)
- 페이크 텔은 쓰지 않는다. 대신 캐릭터가 **평소에도 숨 쉬듯 미세하게 움직이고**, 말할 때는 입이 움직인다.
- 거짓말할 때만 그 움직임 속에 짧은 동요(고유 버릇)가 섞인다. "뭔가 움직이면 거짓말"이 아니라, 평소와 다른 움직임을 알아채야 한다.

### 4.3 난이도별 설정 (`game/lie_system.py`)

| 난이도 | 텔 길이 | 텔 크기 배율 | 거짓말 횟수 (양쪽 동일) |
|---|---|---|---|
| 쉬움 | 1.0초 | 1.6 | 1회 |
| 보통 | 0.7초 | 1.0 | 2회 |
| 어려움 | 0.45초 | 0.55 | 3회 |

- 텔 크기 배율은 움직이는 거리와 표시 크기에 곱해진다. 어려울수록 짧고 작다.

## 5. 플레이어 거짓말과 AI의 의심

### 5.1 플레이어 거짓말 규칙
- 플레이어는 **[예] [아니오] [애매함]** 버튼으로 답한다.
- 거짓말하려면 **[거짓말로 답하기]** 토글을 켜고, 사실과 반대되는 버튼을 누른다. 토글을 켜면 거짓말 횟수가 1 줄어든다.
- 거짓말 횟수는 AI와 같다 (4.3 표).
- 첫 2개 답변에서는 거짓말할 수 없다 (AI와 동일 조건).

### 5.2 심판 LLM (부정 방지)
- 토글 없이 거짓말하면 룰이 무너지므로, **심판 LLM**이 AI의 제시어 기준으로 진실한 답(예/아니오/애매함)을 판정하고 플레이어의 답과 비교한다.

| 토글 | 플레이어 답 vs 진실 | 처리 |
|---|---|---|
| 꺼짐 | 같음 | 정상 진행 |
| 꺼짐 | 다름 | "사실과 다른 답 같아요. 거짓말 토글을 켜거나 답을 고쳐주세요." 경고 |
| 켜짐 | 다름 | 정상 진행 (거짓말 성공적으로 기록) |
| 켜짐 | 같음 | "이건 사실인 것 같아요." 경고 (거짓말 횟수는 쓰지 않음) |
| - | 플레이어 `애매함`, 진실도 `애매함` | 정상 진행 |
| - | 플레이어 `애매함`, 진실은 예/아니오 | "이 질문은 예/아니오로 답할 수 있어요." 경고 (회피 방지) |
| - | 플레이어 예/아니오, 진실은 `애매함` | 정상 진행 (어느 쪽으로 답해도 거짓말로 보지 않음) |

- `애매함`은 거짓말 대상이 아니다. 토글을 켠 상태로 `애매함`을 누를 수 없다.
- 경고는 강제가 아니다. 플레이어가 "그대로 진행"을 누르면 플레이어의 선택을 인정한다 (심판 LLM 판정 오류 대비).

### 5.3 AI는 항상 의심한다
AI는 플레이어의 모든 답을 그대로 믿지 않고, 매번 **"이 답이 거짓말인가?"** 하나만 판단해서 **의심도(0~100)**를 매긴다. 답이 예/아니오라서 무엇이 거짓말인지 모호하지 않다.

**의심 근거 (AI가 알 수 있는 정보만 사용)**

| 근거 | 방법 |
|---|---|
| 예상 답과 비교 | AI가 지금까지의 답으로 좁힌 **후보 단어 목록**을 기준으로, 이번 질문의 답이 무엇일지 LLM으로 예상한다. 예상과 반대 답이 나오면 의심도가 크게 오른다. |
| 후보 붕괴 (미구현) | 이번 답을 받아들이면 모든 답을 만족하는 후보가 하나도 없어질 때 의심도가 크게 오른다. LLM 호출이 추가로 필요해서 보류. |
| 답변 시간 | 평소보다 답하는 데 오래 걸리면 의심도가 오른다 (플레이어의 텔). |
| 후반부 | 게임 후반부(AI 토큰 6개 이하)면 의심도가 오른다. AI는 플레이어가 거짓말을 몇 번 썼는지 모르고, 간파로 확인된 횟수만 안다. 확인된 거짓말로 횟수를 다 썼으면 더 이상 의심하지 않는다. |

**예시** (AI 제시어: 펭귄, AI는 모름)
```
지금까지 답: 동물이다(예), 날 수 있다(아니오), 물에 산다(예)
AI 후보: 펭귄, 물개, 거북이, 돌고래
AI 질문: "털이 있어?" → AI의 예상: 후보 대부분 '아니오'
플레이어 답: "예"  → 예상과 반대 → 의심도 상승
```

**의심도에 따른 행동**

| 의심도 | 행동 | 대사 예시 |
|---|---|---|
| 낮음 | 믿되 한마디는 함 | "흠, 그렇구나. 일단 믿어볼게." |
| 중간 | 압박 대사 | "진짜? 방금 좀 망설인 것 같은데?" |
| 높음 (임계값 이상) | **간파 선언** | "그거 거짓말이지!" |

- 의심도가 낮아도 매번 반응 대사를 한다. 플레이어가 "AI가 날 보고 있다"는 압박을 계속 느끼게 하기 위해서다.
- 가끔은 의심도가 낮은데도 일부러 떠보는 대사를 한다 (블러핑).
- 간파 임계값은 캐릭터 성격에 따라 다르다 (7장).

### 5.4 공정성: 심판 정보는 AI에게 넘기지 않는다
- 심판 LLM은 AI의 제시어를 알고 있다. 이 판정을 AI의 의심에 쓰면 AI가 **항상** 거짓말을 알아채게 되어 게임이 성립하지 않는다.
- 그래서 AI의 의심은 위 표의 정보(AI 자신의 후보 목록, 답변 기록, 답변 시간, 남은 거짓말 횟수)로만 계산한다.
- 각 역할은 별도 LLM 호출로 처리하고 대화 기록을 공유하지 않는다.

### 5.5 AI의 추리 방식
- 간파하지 않은 답이라도 의심도가 높았다면 **신뢰도를 낮게 표시**하고 추리에 반영한다.
- 의심스러운 답 하나에 추리 전체를 걸지 않는다. 후보를 좁힐 때 신뢰도가 높은 답을 우선한다.

## 6. 간파 (양방향)

### 6.1 간파가 왜 필요한가
질문 횟수가 제한돼 있기 때문에 거짓말에 속으면 두 가지 손해를 본다.

1. **질문 1개를 낭비한다.**
2. **잘못된 정보로 추리가 틀어진다.** 이후 질문까지 엉뚱한 방향으로 쓰게 된다.

간파는 이 손해를 되돌리는 수단이다. 그리고 텔을 관찰할 이유를 만들어 준다. 간파가 없으면 텔은 그냥 장식이 된다.

### 6.2 간파 규칙
- 상대의 답 직후, 다음 행동을 하기 전까지만 **[간파!]**를 선언할 수 있다.
- 플레이어와 AI 모두 같은 규칙을 적용한다.

| 결과 | 효과 |
|---|---|
| 성공 | 진실한 답 공개 (뒤집힌 답을 바로잡음), 사용한 질문 토큰 환급 +1 보너스 토큰, 상대 당황 연출 |
| 실패 | 간파한 쪽 질문 토큰 1개 차감, 상대 도발 연출 |

- 실패 페널티가 있어서 아무 때나 누를 수 없다. 확신이 있을 때만 쓰게 된다.

## 7. 캐릭터

### 7.1 성격 타입

| 타입 | 거짓말 빈도 | 버릇 | 의심 성향 (간파 임계값) | 성격 |
|---|---|---|---|---|
| 정직한 타입 | 낮음 | 크고 뚜렷함 | 잘 믿음 (높음) | 입문용, 거짓말할 때 미안해함 |
| 능글맞은 타입 | 높음 | 보통 | 자주 떠봄 (중간) | 도발과 농담이 많음 |
| 포커페이스 타입 | 보통 | 미세함 | 날카로움 (낮음) | 말수가 적고 냉정함, 고급용 |

### 7.2 캐릭터 목록

**도하 (가칭): 첫 번째 정식 캐릭터**

| 항목 | 내용 |
|---|---|
| ID (에셋 폴더) | `honest` |
| 성별 | 남성 |
| 성격 타입 | 정직한 타입 |
| 외형 | 짧은 머리 (양쪽 귀가 다 보임), 헤드밴드 착용. 세부 외형은 생성 후 확정 |
| 헤드밴드 | 헤드밴드 + 제시어 카드 (카드가 붙을 평평한 정면 부분 필요) |
| 거짓말 버릇 (텔) | **귀가 움찔**거림 + 귀 끝이 살짝 붉어짐 |
| 말투 | 반말, 순하고 솔직함. 거짓말한 뒤 살짝 머뭇거림 |

> 루미(`sly`)는 화면 개발용 **임시 캐릭터**다. 도하가 완성되면 기본 상대를 도하로 바꾸고, 루미 에셋은 정식 캐릭터로 쓰지 않는다. 지금 UI 코드(`ui/app.py`)의 캐릭터 이름, 대사, 텔 방식(몸 움찔 + 땀방울)도 루미 기준이라 함께 교체한다.

**로봇 (가칭): 두 번째 캐릭터**

| 항목 | 내용 |
|---|---|
| ID (에셋 폴더) | `robot` |
| 외형 | 작고 귀여운 로봇. 크림색 둥근 몸, 얼굴은 검은 디스플레이 화면(표정 = 앰버 LED), 머리 위 안테나. 헤드밴드에 카드가 그려져 있음 |
| 배치 | 작아서 의자가 아니라 **카페 테이블 위에 앉음** (무대 배치값은 캐릭터별로 `meta.json`) |
| 거짓말 버릇 (텔) | **안테나 끝에 작은 스파크** (회로 이상 = 거짓말) |
| 성격 타입 / 이름 / 말투 | 미정 |
| 에셋 | 표정은 화면 안쪽만 인페인팅 (`tools/gen_sprites.py robot-expr`), 말하기 = 화면 아래 LED 입 조각, 텔 = 안테나 스파크 조각 |

**도하의 버릇 설계**
- 사람 귀는 움찔해도 움직임이 작아서, 귀 끝이 붉어지는 표현을 같이 넣는다. 정직한 타입(입문용)이라 버릇이 너무 숨겨지면 안 된다.
- 움찔은 텔 길이 동안 2번 빠르게 (위로 살짝 → 원위치). 크기는 난이도 배율을 따른다.
- 그래서 머리 모양은 **양쪽 귀가 항상 다 보여야** 한다 (머리카락이 귀를 덮으면 안 됨). 헤드밴드도 귀 위를 지나가되 귀를 가리지 않는다.

**상대 캐릭터 선택**
- 새 게임마다 정식 캐릭터 중 하나를 **무작위로** 고른다 (지금은 도하, 로봇).
- 정식 캐릭터 = `assets/characters/<ID>/` 에 `meta.json` 과 `idle.png` 가 있고, 임시 캐릭터(`sly`)가 아니고, `meta.json` 의 `playable` 이 `false` 가 아닌 캐릭터. `meta.json` 이 깨져 있으면 건너뛴다.
- 정식 캐릭터를 하나도 못 찾으면 임시 캐릭터 **루미**로 시작한다.
- 개발용으로 환경 변수 `HB_CHARACTER=<ID>` 를 주면 항상 그 캐릭터로 시작한다.

### 7.3 캐릭터 모션

| 모션 | 언제 | 표현 |
|---|---|---|
| 대기 (idle) | 기본 | 숨쉬기 (미세한 상하 움직임) |
| 말하기 (talk) | 대사가 찍히는 동안 (질문, 답, 반응 대사 모두) | 입을 뻐끔거림 (idle 입 ↔ talk 입 반복). 대사가 다 찍히면 idle로 돌아감 |
| 거짓말 버릇 (tell) | 거짓말로 답할 때 | 캐릭터별 버릇. 말하기와 동시에 일어날 수 있음 |
| 정답 (correct) | 캐릭터가 자기 제시어를 맞힘 / 플레이어가 정답 도전에 틀림 | 기쁨, 안도 |
| 오답 (wrong) | 캐릭터가 정답 도전에 틀림 / 플레이어가 캐릭터 제시어를 맞힘 | 아쉬움, 분함 |
| 간파당함 (caught) | 플레이어가 거짓말을 간파함 | 당황, 들킨 표정 |
| 의심 (suspicious) | 플레이어 답의 의심도가 중간 (압박 대사) | 실눈, 못 믿겠다는 표정 |
| 간파 선언 (accuse) | 캐릭터가 플레이어의 거짓말을 간파 선언 | 날카롭게 노려봄 |
| 생각 중 (thinking) | 캐릭터가 질문을 고르는 동안 | 시선을 위로, 고민하는 표정 |

- 정답/오답은 상황 4가지를 표정 2개로 처리한다.
- 말하기와 거짓말 버릇은 **동시에** 일어날 수 있어서 (거짓말로 답하면서 말함), 전신 이미지를 통째로 바꾸지 않고 **부위별 조각 이미지를 겹쳐서** 표현한다 (9장).

### 8.2 LLM 역할

| 역할 | 제시어를 아는가 | 입력 | 출력 |
|---|---|---|---|
| 답 판정 (AI 답변용) | 플레이어 제시어 | 질문 | `{"answer": "예/아니오/애매함/무효"}` |
| 반응 대사 | 모름 | 질문, 최종 답(거짓말이면 뒤집힌 답) | 짧은 대사 (정보 없음) |
| AI 턴 (후보 + 질문 + 답 예상) | 모름 | 카테고리, 질문/답 기록 + 의심 표시 | `{"candidates": [...], "question": "...", "expected": "예/아니오/모름", "confidence": 0~1}` 또는 정답 도전 |
| 심판 | AI 제시어 | 질문, 플레이어 답 | `{"answer": "예/아니오/애매함"}` |
| 정답 판정 | 해당 제시어 | 추측 | `{"correct": true/false}` |

- 답 판정과 심판은 JSON 맨 앞에 `fact`(관련 사실 한 문장)를 먼저 쓰게 해서 정확도를 올린다 (헷갈리는 질문 20개 기준 20/20, 평균 0.75초).
- 반응 대사는 제시어를 모르는 별도 호출로 만든다. 진실 판정과 같은 호출에서 대사를 만들면, 거짓말로 답을 뒤집었을 때 대사와 답이 어긋나서 거짓말이 드러나기 때문이다.
- 답 예상은 AI가 질문을 만드는 호출에서 함께 받는다 (추가 호출 없음).
- 의심도는 LLM이 정하지 않고 **코드가 계산**한다. 위 "답 예상" 결과, 후보 붕괴 여부, 답변 시간, 남은 거짓말 횟수를 점수로 합산한다. 덕분에 결과가 일관되고 밸런스 조정이 쉽다.
- **안전장치**
  - 반응 대사에 플레이어 제시어(동의어 포함)가 들어가면 다시 생성한다.
  - 출력 형식이 잘못되면 재시도하고, 그래도 실패하면 `애매함`으로 처리한다.
- 예/아니오 방식이라 진실 턴과 거짓 턴의 LLM 호출 횟수가 같다. 응답 시간 차이로 거짓말이 드러날 걱정이 적다.

### 8.3 캐릭터 연출 (Gradio)
- 캐릭터 영역은 `gr.HTML`로 그린다 (`ui/app.py`, 스타일은 `ui/style.css`). gr.HTML은 스크립트를 실행하지 않으므로 모든 움직임은 CSS 애니메이션으로 한다.
- 숨쉬기: 캐릭터 레이어 전체에 항상 걸린 미세한 `scale` 애니메이션.
- 말하기: 대사 타자 효과의 전체 길이(글자 수 × 글자 간격)를 계산해서, 그 시간 동안만 입 조각을 깜빡이게 한다 (`steps` 애니메이션). 끝나면 idle 입으로 남는다.
- 거짓말 버릇: 텔 길이와 크기 배율을 CSS 변수(`--tell-dur`, `--tell-amp`)로 넣는다. 도하는 귀 조각을 움찔 + 붉게, 로봇은 안테나 스파크 조각(`part_tell.png`)이 텔 길이 동안 지직거린다.
- 캐릭터 설정은 `assets/characters/<ID>/meta.json` 을 읽는다 (이름, 무대 배치 `stage`, 카드 위치 `headband_card`, 표정 연결 `face_map`, 고정 대사 `lines`, 버릇 연출 `tell_fx`: `spark`/`twitch`, 연출 중심 `tell_origin`). 상대 캐릭터는 새 게임마다 무작위로 정해서 게임 객체에 붙인다 (7.2 상대 캐릭터 선택).
- 플레이어 답변 시간은 AI 질문이 화면에 표시된 시점부터 버튼을 누를 때까지 측정한다.

### 8.4 실행 환경
- GPU: RTX 5070 Ti Laptop (VRAM 12GB)
- LLM: `qwen3:14b` (약 9.3GB). thinking 모드는 응답 속도 때문에 끈다.
- ComfyUI와 LLM을 동시에 돌리면 VRAM이 부족하다. **스프라이트는 개발 중에 미리 생성**하고, 게임 실행 중에는 LLM만 쓴다.
- 응답 속도 목표: 답변 1회 3초 이내

## 9. 아트 리소스 (ComfyUI)

### 9.1 제작 원칙
- 오리지널 캐릭터로 디자인한다 (기존 게임 캐릭터나 그림체를 따라 하지 않음).
- 캐릭터마다 기본 이미지(`idle.png`) 1장을 먼저 뽑고, 나머지는 모두 **인페인팅으로 해당 부위만** 바꾼다. 그래야 같은 캐릭터로 보이고 **헤드밴드 위치가 그대로라서** 제시어 카드가 어긋나지 않는다.
- 화풍과 규격: 카페 배경과 어울리는 스타일 문구(애니메이션 셀 셰이딩, 깔끔한 선, 따뜻한 조명, 비주얼노벨 스프라이트), 크기 832×1216, 정면 상반신 구도. 무대 배치값(`CHAR_HEIGHT`, `CHAR_TOP`)을 그대로 쓸 수 있게 머리 위치와 크기를 임시 캐릭터와 비슷하게 맞춘다.
- 생성 기록(모델, 프롬프트, 시드, 마스크)은 캐릭터 폴더의 `meta.json`에 남긴다. 헤드밴드 카드 좌표(`headband_card`)도 여기에 둔다.

### 9.2 파일 구성

**전신 이미지 (표정 전체가 바뀌는 모션)**

| 파일 | 모션 | 비고 |
|---|---|---|
| `idle.png` | 대기 | 기본 이미지. 나머지는 모두 이걸 인페인팅 |
| `correct.png` | 정답 (기쁨, 안도) | 얼굴 영역 인페인팅 |
| `wrong.png` | 오답 (아쉬움, 분함) | 얼굴 영역 인페인팅 |
| `caught.png` | 간파당함 (당황) | 얼굴 영역 인페인팅 |
| `suspicious.png` | 의심 | 얼굴 영역 인페인팅 |
| `accuse.png` | 간파 선언 | 얼굴 영역 인페인팅 |
| `thinking.png` | 생각 중 | 얼굴 영역 인페인팅 |

**부위 조각 (기본 이미지 위에 겹쳐서 움직이는 모션)**

| 파일 | 모션 | 비고 |
|---|---|---|
| `part_talk.png` | 말하기 (입 벌림) | 입 주변만 인페인팅한 뒤, 입 영역만 잘라서 투명 PNG로 저장. 같은 캔버스 크기(832×1216)라 좌표 계산이 필요 없음 |
| `part_tell.png` | 거짓말 버릇 | 귀가 살짝 들리고 귀 끝이 붉은 귀 조각 (양쪽 귀) |

- 조각은 전신 이미지와 같은 크기의 투명 PNG로 저장해서, 기본 이미지와 같은 자리에 그대로 겹친다.
- 표정 전신 이미지(정답/오답/간파당함)가 보이는 동안 말할 때는 입 조각이 표정과 안 맞을 수 있으므로, 그때는 말하기 조각을 쓰지 않는다 (표정 이미지 그대로 대사만 찍힘).
- 위 표에 없는 상황(의심, 간파 선언 등)은 `idle.png` + 대사로 처리한다. 필요해지면 표정을 추가한다.

## 11. 미정 사항

- [ ] 질문 토큰 수 (현재 15개, 플레이테스트로 조정)
- [ ] 간파 성공 보상 크기 (현재 환급 +1 보너스)
- [ ] `애매함` 답 횟수 제한 여부
- [ ] AI 의심도 점수 배분과 간파 임계값, 답변 시간 기준
- [ ] 제시어 카테고리와 단어 수 (1차 목표: 4개 카테고리 × 50단어)
- [ ] 게임 제목
- [ ] 남자 캐릭터 이름 (가칭 도하)과 세부 외형
- [x] 판마다 상대 캐릭터를 고르는 방식 → 무작위 (정식 캐릭터가 없으면 루미)
- [ ] 캐릭터 성격을 LLM 대사(반응 대사, 의심 대사)에도 반영할지. 지금은 고정 대사(`lines`)만 캐릭터별로 다르다
